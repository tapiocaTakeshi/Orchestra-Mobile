# Claude 風デザイン方針（Designer 作業記録・Coder への設計図）

> この文書は Designer（タスク 1/3）が既存画面を整理し、Claude 風のデザイン方針を策定したものです。
> 後続の Coder はこの方針に沿って改修し、Reviewer はこの文書と照合して確認します。
> 前提: ブランド指定はユーザーから与えられていないため、Claude のアプリの雰囲気（暖色・余白・落ち着いた会話体験）を参考にした独自のトークン体系とする。既存の機能・画面遷移・型安全性は変えない。

## 0. 現状の把握（調査結果）

### 技術基盤
- Expo / React Native 0.81 / React 19 / TypeScript。UI は自前コンポーネント（`src/components/ui.tsx`）と画面コンポーネントで構成。
- 色・余白・角丸・文字サイズは `src/theme.ts` のトークンに集約済みで、全画面が参照している。トークン名は従来（暗い配色時代）のまま維持されているため、値の差し替えだけで全体へ波及する構造。
- フォントはカスタムフォントの読み込みなし。見出しのみ `Platform.select({ ios: 'Georgia', android: 'serif' })` の端末セリフ体、コード系は `Menlo / monospace` を使用（`CloudAgentsScreen.tsx` の `SERIF` / `MONO`）。
- 画面遷移: タブバーなし。ホーム（`CloudAgentsScreen` 内蔵）＋ナビゲーションドロワー＋ページスタック（`App.tsx` の `stack` / `pushPage`）。Android 戻るキー対応済み。

### 検証手段（後続へ引き継ぎ）
- 型チェック: `npm run typecheck`（`tsc --noEmit`）。依存インストール後に実行し、**現状 exit 0（成功）を確認済み**。
- テスト: `npx jest --runInBand`（31 スイート・390 件。並列実行はサンドボックスのメモリ不足で Killed になるため `--runInBand` 必須）。
- Web 描画確認: `npx expo export --platform web` が成功する。
- 注意: ログイン後の画面は認証情報がないため実描画は未確認。iOS/Android 実機での StatusBar・セリフ体・影の見え方は Reviewer が確認する。

## 1. デザインの方向性

- 地は暖かいオフホワイト `#faf9f5`、カードと入力欄は白 `#ffffff`。ナビゲーションドロワーだけ一段沈んだ `#f0eee6` で本文と分ける。
- 文字は濃い茶系（本文 `#3d3929` / 見出し `#1f1e1b` / 補足 `#5e5a4c` / 薄い補足 `#78735f`）。地の上で 4.5:1 以上を保つ。
- アクセントは控えめなテラコッタ `#b95a3a`（白文字とのコントラスト 4.58）。主な操作（送信・主ボタン）とリンク・選択印だけに使い、面で多用しない。
- 余白は 4/8/12/16/24 の 5 段階。角丸は 8/12/16（入力欄の箱は 24、チップは全丸 999）。影はごく薄く（`shadowOpacity: 0.06` 程度）、縁は `#e6e2d6` の淡い線で。
- タイポグラフィは既存のまま: 本文 15px / line-height 22〜23、見出しのみセリフ体で会話の落ち着きを出す。等幅はメタ情報とコードに限定する。
- 新しい UI 要素は原則追加しない。既存要素の配色・スタイル置き換えを優先し、整理後も主目的を達成できない場合だけ既存要素との置換で提案する。

## 2. 主要画面の主目的と UI 整理（追加より先に整理）

| 画面 | 主目的（1 文） | 目的に無関係・操作を妨げる要素 | 判断 |
|---|---|---|---|
| ホーム（一覧＋入力欄、`CloudAgentsScreen` 内蔵） | 指示を書いてエージェントを起動し、セッションの状況を見る | 入力欄下の設定チップが常時 5〜6 個並ぶ（送り先／始める場所／モデル／ループ／承認モード／並列数／コスト）。既定値の「ループ · オフ」は情報量がなく欄を圧迫する | 「ループ」チップは**必要時のみ表示**（既定値 `off` 以外のときだけ）。変更は「始める場所」「モデル」チップから開く起動設定シートで従来どおり可能で、変更後はチップとして見える状態を保つ。それ以外のチップは初期値が意味を持つため維持 |
| ホーム（一覧の絞り込みタブ） | 同上 | 「全て／稼働中／承認待ち／エラー」の絞り込み | **必要時のみ表示**の既存実装（6 件以上か絞り込み中だけ表示）を維持。削除しない（見つけられなくなる機能のため段階的開示） |
| ホーム（上部ヘッダ） | 接続状態を確認しドロワーを開く | タイトル＋接続状態の 2 行のみで過剰な要素なし | 維持。配色のみトークン適用 |
| ナビゲーションドロワー | 他ページへ移動する | なし（閉じているときは完全非表示でレールを残さない設計済み） | 維持。配色のみ変更 |
| ページ表示中の承認の帯（`App.tsx` の `approvalBar`） | 承認待ちに気づいてチャットへ戻る | 操作を遮るモーダルではなく画面上部の細い帯 | 維持（承認待ちの通知は取り消し手段の入口のため削除不可）。主張を抑えた配色にする |
| ログイン（`LoginScreen`） | ログインする | 規約同意チェック＋ログインボタン＋手動ペアリングリンクのみ | 維持。主ボタンだけアクセント色。手動ペアリングは入口を残す（発見性を失わせない） |
| アカウントシート | 接続・コスト・ログアウトに辿り着く | 接続中のみの行（接続設定／切断）は条件表示済み | 維持。ログアウトは確認ダイアログ付きの取り消し可能な導線を維持 |
| クラウド詳細（チャット） | ログを読み、追加指示・承認・停止を行う | ツール実行は「ツールを N 回実行」に畳む設計済み。差分は「±」ピルから開く | 維持。吹き出し・入力欄のスタイルのみ Claude 風に整える |
| カンバン／プロジェクト／MCP／共有／コスト／クイック操作／接続 | 各機能（カンバン操作・役割割当・MCP 追加・共有・コスト方針・エディタ操作・接続管理） | 各画面とも目的外の固定バー・モーダルは見当たらない | 配色・余白の統一のみ。機能・操作は変更しない |

判断の原則:
- 発見できなくなる機能や取り消し手段は削除せず、段階的開示（シート・条件表示）に留める。
- 既定値から変更された設定（ループ、承認モード、並列数）はチップとして見える状態を保つ。
- 頻繁な選択には適切な初期値がある（送り先=クラウド、モデル=前回値、ループ=off）。初期値を持つチップは警告（`warn`）時だけ注意色を出す。
- 同時に多すぎる選択肢は入力欄下のチップに集約し、詳細設定はシートへ移動済み。この構造を維持する。

## 3. デザイントークン（`src/theme.ts` の値をそのまま採用・Coder もここだけを変える）

```
bg: '#faf9f5'        画面の地（暖かいオフホワイト）
bgSidebar: '#f0eee6' ドロワーの地
bgElevated: '#ffffff' カード・入力欄の箱
bgInput: '#ffffff'    1 行入力欄
bgHover: '#ebe8de'    押下時・自分の吹き出し
border: '#e6e2d6'     淡い線
borderStrong: '#d6d1c3'

fg: '#3d3929'        本文
fgStrong: '#1f1e1b'  見出し
fgMuted: '#5e5a4c'   補足
fgFaint: '#78735f'   プレースホルダ（地上で 4.5:1 以上）

accent: '#b95a3a'        主ボタン・送信の塗り（白文字で 4.5:1 以上）
accentPressed: '#a24f30'
onAccent: '#ffffff'      accent の塗りの上の文字
accentText: '#b5532f'    リンク・選択印の文字色

success: '#2f7d4f'
warning: '#9c610c'   「確認待ち」ドット・チップの警告
danger: '#b3261e'
running: '#3b6db3'   「作業中」の印

scrim: 'rgba(31,30,27,0.32)'  ドロワー・シートの後ろ
shadow: '#3d3929'    影の色（opacity 0.06 程度で使う）

spacing: xs 4 / sm 8 / md 12 / lg 16 / xl 24
radius: sm 8 / md 12 / lg 16 （入力欄の箱 24、チップ・ピル 999）
fontSize: xs 12 / sm 15 / md 17 / lg 22 / xl 30
```

旧配色の名残で「濃い塗り＋`colors.bg` の文字」になっている箇所は、ライト配色では見えなくなるため、すべて `accent` ＋ `onAccent` の組み合わせに置き換える。

## 4. 会話画面（メッセージと入力欄）の仕様

- 入力欄（composer）: 白い箱（`bgElevated`）、角丸 24、淡い縁 `border`、ごく薄い影。内側の入力は minHeight 44 / maxHeight 160、本文 15px・lineHeight 21。送信ボタンは角丸のある正方形（34×34）で `accent` 塗り・`onAccent` アイコン。無効時は `opacity 0.4`。
- 自分の指示: 右寄せの吹き出し。背景は `bgHover`（暖かい薄ベージュ）、角丸 20・右下だけ 6、文字は `fg` 15px / lineHeight 22。左側に `spacing.xl * 2` の余白を取り長文を読みやすくする。
- エージェントの返答: 左にアイコン（✻、`accent` の淡色 `withAlpha(accent,'1f')` の丸）と名前を 1 度だけ出し、本文はアイコン分（34px）下げて揃える。本文 15px / lineHeight 23。
- ツール実行は 1 行に畳み（「ツールを N 回実行」）、開くと等幅の 2 行（● 名前 / ⎿ 出力）。作業中は点が順に光る `TypingBubble` と経過時間。
- メタ情報（時刻・モデル・ファイル数）は等幅 12px、`fgFaint`。

## 5. 評価指標

- 指標: **会話画面で入力開始から送信完了までに必要な操作数**。
- 現状値: **2 操作**（入力欄をタップして文字を入力 → 送信ボタンを 1 タップ）。送信は入力欄の右下のボタン 1 つで完了し、確認ダイアログや中間画面は挟まない。
- 確認手順: ホーム（クラウド一覧）の入力欄に 1 文字以上入力し、送信ボタンをタップしてセッションが起動することを確認する。PC 送り先の場合も同じ 2 操作。`npm run typecheck` と `npx jest --runInBand` で回帰がないことを併せて確認する。
- 目標: 改修後も 2 操作を維持する（増やさない）。チップ整理により既定状態で表示されるチップは 1 つ減り、入力欄の視認性は上がる。
