この画面の主タスク

混在一覧で進行・承認・接続状態を確認し、新しい指示を1度の送信で開始する。優先カードや新規会話ボタンは足さず、既存の一覧・ショートカット・入力欄の順序と遷移を維持します。

視線: 56px header → 条件付きshortcut → listの状態・件数 → 行title/meta → 下部composer。承認待ち帯は待ちがある時だけ表示し、通常は余白を残しません。

Composerの条件と操作領域

chip順は送り先(homeのみ)→始める場所→モデル→承認設定(Divisionのみ)→並列数(2以上)→コスト。PC送り先は送り先とコストだけを出し、ループchipは追加しません。下はPC送り先・空入力の例です。

chipの見た目は28px・12px/600・padding 4px 10px・radius 999px。実Pressableの高さはiOS 44pt／Android 48dpを目標にし、hitSlopだけに依存しません。PC送信中はspinner・disabled・busy、空入力はopacity .45＋disabled＋理由を併用。送信は44×44px・radius 8pxでscroll外に固定します。

filterは6件以上または絞り込み中のみ。狭幅では時刻→補助metaの順に省略し、titleと状態名を欠落させません。金額不明を0ドルと推定せず、既知の合計だけを表示します。

絞り込み結果なし: filterと件数を残し、「稼働中のセッションはありません。」等を表示。「全て」へ戻る操作を残す。停止は「○○を停止」の44×44pt以上、接続中はspinner＋「接続しています…」、offlineはwifi-off＋「接続切れ」と次の案内。

PC新規チャットの復帰

sendToPc開始
promptをsnapshot→newThread→sendPrompt→成功
PC会話を開く

pendingPcSend = { prompt, stage:'newThread'|'sendPrompt', client, threadId? } を失敗まで保持。newThread失敗時のみ同じPCでthread作成からやり直す。newThread成功時は戻り値ChatStateのthreadIdを保持し、その後のsendPrompt失敗では client.sendPrompt(prompt,{threadId}) だけを再試行。新しいthreadを作り直さず、active threadの暗黙依存も避ける。

本文送信失敗（入力欄直上の表示）

PCへの本文を送信できませんでした

チャットは作成済みです。本文は保持しているので、同じチャットへ本文だけを再送できます。

再試行は保持したthreadIdへsendPromptするだけ。newThreadは呼ばず、チャットを重複作成しません。

接続切れで再試行不能

現在は再試行できません

PCとの接続が切れています。本文と作成済みのthreadIdは保持しています。

再接続後に「同じチャットへ再試行」を表示します。自動再送はしません。

再接続は既存transportの操作を使い、同じPCと保持したthreadIdを維持する。送信成功時のみdraftを消してPC会話を開く。draft編集・対象送信成功・別の送信先選択で古いerrorとpendingPcSendを解除。エラーは入力直上に1つだけ出し、toastを重ねない。再試行・再接続は44×44pt以上、処理中は同じボタンを無効化してfocusを保つ。利用者が再接続した場合、成功後は保留中の再試行へfocusを戻す。

2026-11-08: ISS-09/10/12を反映し、失敗例・同一thread再送・不能状態を追加。通常時のホーム構成と既存の接続導線は主タスクを阻害しないため維持。

フォーカス・キーボード・戻る

  1. 初期focusは画面見出し。Screen readerには「接続済み、実行中2件、承認待ち1件」を順に読ませます。
  2. メニュー→承認帯（ある時）→shortcut→filter→一覧行／停止→入力→chips→送信の順。装飾アイコンはfocus対象外。
  3. 起動成功後は詳細見出しへfocus。失敗時はinline errorへfocusし、再試行中は同じボタンへfocusを維持。
  4. Android戻るは開いている設定シート→ドロワー→前ページの順。未送信文は遷移しても保持します。

受け入れ時の成功指標

通常起動は「入力→送信」の2操作。失敗後の再試行は値を入れ直さず1操作。送信開始から100ms以内に押下状態と「起動中…」を表示し、320pxで入力・送信・エラーが横に溢れません。
