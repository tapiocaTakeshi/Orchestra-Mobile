ORCHESTRA MOBILE / UX IMPROVEMENT

迷わず送り、状態を確かめ、安全に戻れる。

既存の暖色・画面構成・操作資産を維持し、状態の理解と操作の回復しやすさを改善する実装用設計書です。

前提: 調査資料には実測所見がないため、実装確認と仕様書の要件を根拠に設計します。利用者テストの結果とは区別します。対象は React Native アプリ、参照用Webモックは同じ情報設計を採用します。

Visual Theme & Atmosphere

主タスクは「エージェントへ指示を送り、進行と承認を把握する」です。紙のような暖色の背景、落ち着いたテラコッタ、十分な余白で、長文の指示とログを主役にします。装飾より状態ラベルと次の操作を優先します。

密度は本文15px・行間1.65を基準に、会話はゆったり、設定は compact に。通常時は接続状態・戻る・画面名だけを上部に残し、詳細設定や補助説明は必要時に開きます。主要ボタンは1画面1つに絞ります。

Less is more: 常設サイドバー、重複バナー、連続する通知、似た主ボタンを置かず、入力・状態・送信の視線を遮りません。操作数は通常送信「入力→送信」の2操作、失敗後「再試行」の1操作を成功指標とします。

  • 状態は色＋日本語の文字＋必要時のアイコンで表す
  • 入力値を操作の途中で失わない
  • 戻る・閉じる・再接続を予測可能にする
  • 待機中は進行中であることを即座に示す

Composer chips / Fixed send

送り先: Cloud⌄場所: Mobile⌄! モデル未選択

chipは見た目28px・12px/600・padding 4px 10px・radius 999px。実PressableはiOS 44pt／Android 48dpをmin-heightとし、chip間8px。右端の次項目の断片とfadeでscrollを示し、送信44×44px・radius 8pxは外側に固定。

順: 送り先(homeのみ)→場所→モデル→承認(Divisionのみ)→並列数(2以上)→コスト。PCは送り先・コストのみ。ループchipは追加しない。空／PC送信中はopacity .45＋disabled、処理中はspinner＋「送信中」。

Filter / Approval band

✓ 全て 6 稼働中 2 承認待ち 1 エラー 1

! 承認待ちがあります チャットへ

filterは6件以上または絞り込み中のみ表示し、選択は枠＋check＋accessibilityState。0件はfilter別の説明。承認帯はページ上部に待ちがある時だけ描画し、説明と導線を折返せる。料金は既知の合計のみを示し、不明を0円にしない。

Inline error / Retry

PCへ送信できませんでした

入力は保持しています。接続を確認して同じ本文を再送してください。

入力直上に44×44pt以上の再試行を置く。失敗時はerror、再試行中はbuttonへfocusを保つ。再試行不能時はbuttonを消し、理由と次の有効操作をpolite通知。自動再送しない。

Sheet / Dialog

変更を破棄しますか？

保存していない内容があります。

Mobileは下シート、Webは中央dialog。radius 16px、padding 24px、scrim。初期focusは安全な「編集を続ける」。Escape/戻るはキャンセル、閉じ後は元の操作へfocus。

Layout Principles

list左右16px、行間の区切り、composer外側12pxを基本に、状態と主操作を最初の画面内に置きます。詳細設定・診断情報・危険操作は必要時まで隠し、削除確認は残します。優先card・新規会話button・常設navを足さず、既存のshortcut・filter・料金導線は低い階層で維持します。

Depth & Elevation

Level 0 — Base

bg、影なし。画面・会話の通常領域。borderは必要な区切りだけ。

Level 1 — Resting

elevated＋shadow-1。一覧・入力カード。視線を過度に奪わない。

Level 2 — Sticky

elevated＋shadow-2。下部composer、sticky header。スクロール時のみ影を付ける。

Level 3 — Overlay

elevated＋shadow-3＋scrim。シート・確認dialog。背後の操作を無効化。

面の順序は Base → Card → Sticky → Overlay。toastはOverlayより手前だが、入力欄や承認ボタンを覆う位置には置かず、画面内errorと重複表示しません。

Do's and Don'ts

Do

  • 接続・実行・失敗を日本語で常に明示する。
  • 送信中はボタンを「送信中…」にし、完了まで無効化する。
  • 失敗時は本文を保持し、入力欄近くに再試行を置く。
  • 高度な設定・診断情報はdisclosureに隠す。
  • 主ボタンを1つに絞り、破壊操作は確認する。
  • シート／ドロワーを閉じたらfocusを起点へ戻す。
  • 44×44pxのhit areaを見た目より優先する。
  • 成功は短いtoast、継続的状態は画面内に表示する。

Don't

  • 色やspinnerだけで状態を伝えない。
  • 常設のバーやbannerを複数段に重ねない。
  • エラー一覧と歓迎用の空状態を同時に出さない。
  • 失敗・切断・戻る操作で入力を消さない。
  • 送信・起動を連打可能なままにしない。
  • toastだけで再試行が必要な失敗を流さない。
  • 同じ見た目の主ボタンを横に並べない。
  • 未実装の認証方法や機能を案内しない。
