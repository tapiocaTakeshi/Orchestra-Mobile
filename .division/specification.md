# デザイン改善仕様書

## 概要・目的

ホームを中心に、既存の暖色系ブランドと操作導線を保ちながら、情報の優先順位、文字の読みやすさ、操作状態の判別性を改善する。改善の優先順位は、主要操作・状態の識別（P0）、ホームの情報階層と余白（P1）、今回の対象範囲に限った共通部品・トークンの整合（P2）とする（`.division/paper.md` §背景・目的、§比較・評価）。

本書は既存実装をデザイン改善するための仕様であり、新しい機能や画面遷移、設定の意味・既定値、データ/APIを追加・変更しない。対象画面以外の全面的な再設計も行わない。

## 対象ユーザー

- iOS、Android、Web で、Orchestra のクラウドエージェントまたは接続中 PC のチャットを利用するログイン済みユーザー。
- 画面幅が狭い端末、大きな文字設定、キーボード、スクリーンリーダーを利用するユーザーを含む。

## 機能要件

### デザイン方針・共通要件

- **FR-001 ブランドと階層:** `src/theme.ts` の暖色オフホワイト、濃い茶系文字、控えめなテラコッタを基準にする。アクセント色は主操作・リンクに限定し、画面背景、カード／入力欄、枠線、補足情報を色・余白・文字階層で区別する。見出し・本文・補足の役割を統一し、既存のセリフ体見出しと抑制した影の方向性を保つ。（根拠: paper §背景・目的、§調査結果 5）
- **FR-002 トークンの限定利用:** 本タスクで変更する画面・部品は既存 `src/theme.ts` の色・文字・余白・角丸トークンを優先して使う。`src/design/tokens.ts` 等との全体統合、トークン名の一括変更、未調査画面への一斉適用はしない。必要な値を追加する場合は既存の用途と重複を確認し、意味のある名前を付ける。（根拠: paper §調査結果 5、§比較・評価 P2）
- **FR-003 状態の二重表現:** 稼働中、承認待ち、エラー、警告、選択、押下、フォーカス、無効、処理中は色だけで区別しない。状態名、アイコン、形状、選択表示、説明文のうち少なくとも一つを色に併用し、見た目と読み上げ状態を一致させる。（根拠: paper §外部根拠、§比較・評価 P0）
- **FR-004 読みやすさ:** 本文の文字は OS の文字拡大を妨げず、テキストを含む領域に固定高を設けて拡大時の切れを起こさない。長い日本語・英語ラベルは、操作名や状態名を欠落させず、必要に応じて折り返す。省略表示を使う場合も完全な内容をアクセシブル名で提供する。（根拠: paper §外部根拠、§後続工程での確認方法）
- **FR-005 タッチ・キーボード操作:** 操作可能領域を見た目のアイコン寸法と区別して確保する。iOS は標準 44 pt、Android は 48 dp を目標とし、Web は WCAG 2.2 AA を適用して操作可能領域と隣接操作との干渉を検証する。寸法基準をプラットフォーム間で同一視しない。キーボード操作ではフォーカス位置を視認可能にし、操作順を維持する。（根拠: paper §外部根拠）
- **FR-006 コントラスト:** Web の通常文字は WCAG 2.2 AA の 4.5:1 以上、大きな文字は 3:1 以上を満たす。ネイティブ画面では同じ数値を共通の設計・検証目安として記録し、プラットフォーム適合の断定とは区別する。特に補足・無効・警告・アクセントの文字と実際の背景の組み合わせを測定する。（根拠: paper §外部根拠、§後続工程での確認方法）

### ホーム：クラウド／PC 混在一覧と入力欄

- **FR-007 ヘッダーとショートカット:** ホームのメニューアイコン、Orchestra 見出し、PC 接続状態を維持する。プロジェクト・コスト・カンバンのショートカットは一覧より低い視覚階層とし、横方向に続くことが分かる表示にする。PC 未接続で利用できない項目は鍵と説明を維持し、利用可能項目と区別できるコントラストを確保する。（根拠: paper §調査結果 2、§比較・評価 P1、FILE §2）
- **FR-008 一覧の階層:** クラウドセッション、PC チャット、接続可能な PC の既存混在一覧を維持する。各行はタイトルを第一階層、状態・PC／リポジトリ・時刻・料金等を第二階層として整理する。ステータスは名称またはアイコンと色を併用する。タイトルと必須状態名は幅が狭い場合も隠さず、時刻や補助メタ情報から省略する。（根拠: paper §調査結果 2–3、§比較・評価 P1）
- **FR-009 フィルターと料金:** 「全て／稼働中／承認待ち／エラー」のフィルター、件数、選択状態、絞り込み結果なしの説明を維持する。リストが長いときに表示する既存条件と、絞り込み中は常に戻せる既存条件を変えない。料金が判明しているときの合計とコスト画面への導線を維持する。（根拠: paper §調査結果 2–3、FILE §2）
- **FR-010 入力欄の情報整理:** 入力欄、指示テキスト、設定チップ、送信ボタンを視覚的に一つのまとまりとして配置し、一覧との境界を背景・余白・控えめな枠／影で示す。チップの現行順序と条件を維持する。送り先（ホームのみ）、始める場所、モデル、（Division モード時のみ）承認設定、（並列数が 1 より大きい場合のみ）並列数、コストを表示する。PC 送り先では始める場所・モデル・承認・並列数を表示しない。チップ列は横スクロール可能なままにし、スクロール可能であることを示す視覚的手掛かりを設ける。送信ボタンはチップのスクロールに巻き込まず常に表示する。狭幅でコスト等が初期表示領域から外れても、スクロールで到達可能にする。（根拠: paper §調査結果 2、§比較・評価 P1、§アイデア・提案 1、FILE §3）
- **FR-011 チップ状態:** 設定未選択・不正・確認中は、現行の警告状態を入力欄の該当チップにも反映する。警告は警告色だけに依存せず、文言またはアイコン／形状で判別できるようにする。チップの文字は拡大時に切れず、操作領域はチップの見た目の高さ（現状 28）だけに依存しない。（根拠: paper §調査結果 3、§比較・評価 P0）
- **FR-012 送信ボタン状態:** 空の指示、PC 送信処理中は送信を無効にし、無効／処理中の状態を視覚的・アクセシビリティ上も明示する。処理中は既存ローディング表示を維持する。送信ボタンは主要操作として実寸のタッチ領域を維持または拡大し、チップ列や画面端と重ねない。（根拠: paper §調査結果 3、§比較・評価 P0）
- **FR-013 既存の起動・送信動作:** クラウド起動、PC への新規チャット作成・送信、失敗後の再試行、同一チャットへの再送、入力本文保持の既存動作を変えない。送り先切替、設定シート、コストシートを開く操作も維持する。（根拠: paper §背景・目的、CloudAgentsScreen の既存実装）
- **FR-014 ループ設定:** 現行のクラウド入力欄に「ループ」チップを追加しない。ループ・目標の設定は既存のワークフロー側にあるものとして扱い、Remote 画面のループ切替の意味・導線もこのデザイン改善では変更しない。旧デザイン資料と実装の不一致は解消済みとみなさず、後続工程へ引き継ぐ。（根拠: paper §調査結果 6、§未検証事項、FILE §3）
- **FR-015 一覧状態:** 初回取得中はローディング表示、取得成功で一覧が空なら既存の歓迎表示、取得失敗なら空の歓迎表示を出さず再試行可能なエラー表示、更新中は既存データを残したまま更新状態を示す。絞り込み結果がゼロならフィルター別の空説明を出す。起動中表示、プル更新、起動失敗、PC 送信失敗と再試行／再接続案内を維持し、状態を色だけで区別しない。（根拠: paper §後続工程での確認方法、CloudAgentsScreen の既存状態分岐）

### ホーム：ドロワー、アカウント、承認待ち帯

- **FR-016 ドロワー:** 初期状態ではドロワーを描画せず、ホーム本文に幅・余白・操作領域を残さない。開いたときはメニュー項目、最近の会話、下端のアカウントを一貫した行間・文字階層で表示する。閉じるボタン、背景タップ、Android 戻るキーの既存操作を維持する。ロック項目は鍵と説明を残し、利用可能項目との判別を色だけに任せない。（根拠: paper §調査結果 2、FILE §2）
- **FR-017 最近の会話の状態:** 読み込み中、会話なし、読み込み失敗を互いに区別する。失敗時は再試行を表示し、失敗を「会話なし」と誤認させない。各会話を選択すると既存のクラウド画面へ移動する。（根拠: HomeScreen の既存実装、paper §後続工程での確認方法）
- **FR-018 アカウントと承認:** アカウントシートの接続設定、接続解除、コスト方針、ログアウト確認の既存操作を保つ。承認待ち時はページ上部の帯と「チャットへ」導線を表示し、承認待ちがない場合は帯の余白を残さない。帯は状態を文字・アイコンと色で示し、文字拡大でリンクや説明が切れない。（根拠: paper §調査結果 2、App.tsx の既存実装）

### 共通 UI・幅／セーフエリア

- **FR-019 共通部品:** `src/components/ui.tsx` の Button、IconButton、Input、SegmentedControl、EmptyState、ErrorBanner、Loading、Drawer、Sheet 等の既存部品と状態 API を優先して使う。ホーム固有部品を共通化する場合は、この対象内での再利用・挙動を確認し、画面外へ不用意に影響を広げない。（根拠: paper §調査結果 4–5、§比較・評価 P2）
- **FR-020 狭幅・広幅:** Web の CSS viewport 320 px、375 px、768 px で横方向のページスクロール、重なり、切れを起こさない。320 px では主要ヘッダー・送信ボタンが常時見え、チップ列のみが独立して横スクロールする。768 px 以上でも既存の単一カラム／ページスタックを維持し、未指定の新しいサイドバーやタブバーを追加しない。ネイティブでは実際の論理幅に合わせて同じ可視性を確認する。（根拠: paper §調査結果 2–3、§未検証事項）
- **FR-021 セーフエリア・キーボード:** ルート、ドロワー、シートは既存の SafeAreaView／safe-area inset の使い分けを維持し、ノッチ、ステータスバー、ホームインジケーター、Android システム領域と重ねない。入力フォーカス時はキーボードを避ける既存挙動を維持し、入力欄・送信ボタンがキーボードに隠れない。内容が表示領域を超える場合は該当領域をスクロール可能にする。（根拠: App.tsx、ui.tsx、CloudAgentsScreen.tsx の既存実装）

## 非機能要件

- **NFR-001 文字拡大:** React Native の文字拡大を無効化しない。ネイティブは OS の大きな文字設定および標準比 200% を目標に確認する。文字拡大時に主要操作、状態名、エラー、送信ボタンが切れたり操作不能になったりしない。Web はブラウザー拡大時にも横スクロールをページ全体へ発生させない。（根拠: paper 冒頭 Searcher メモ、§後続工程での確認方法）
- **NFR-002 アクセシビリティ:** 操作要素は役割、意味のあるアクセシブル名、選択／無効／展開／処理中等の状態を支援 API で公開する。装飾アイコンは重複読み上げしない。状態変化は既存の live region／alert 等を活用する。色以外の視覚手掛かりを併用する。（根拠: paper §外部根拠、既存 ui.tsx）
- **NFR-003 コントラストと操作寸法:** Web では FR-006 の WCAG 2.2 AA を満たす。iOS の pt、Android の dp、Web の CSS px を別々に計測して記録する。操作対象間の誤タップ、フォーカスの遮蔽がないことを確認する。（根拠: paper §外部根拠）
- **NFR-004 回帰:** `npm run typecheck`、`npx jest --runInBand`、`npm run build:web` を実施する。特に CloudAgentsScreen、HomeScreen、RemoteScreen、およびデザイントークン関連テストを確認する。テスト・ビルド未実施の結果を合格と記載しない。（根拠: paper §後続工程での確認方法、FILE §7）
- **NFR-005 範囲:** 新規依存、API／データ形式変更、認証変更、未対象画面の外観変更を加えない。見た目の変更で既存操作の到達性や手順を増やさない。（根拠: paper §背景・目的、§比較・評価）

## 画面・フロー一覧

| 画面／部品 | 入口・遷移 | この仕様で扱う範囲 |
|---|---|---|
| ホーム（クラウド／PC 混在一覧） | ログイン・規約同意後に表示。行選択でクラウド詳細または PC チャットへ | ヘッダー、ショートカット、一覧階層、フィルター、料金、読み込み・空・エラー |
| 入力欄（ホーム） | ホーム下部に固定。設定・送り先・コストは既存シート、送信は既存起動／PC 送信へ | チップ列、入力欄、送信状態、幅・キーボード対応 |
| ナビゲーションドロワー | ホームのメニューから開閉。ページ選択でドロワーを閉じてページスタックへ | 行の階層、ロック、最近の会話、読み込み・空・エラー、アカウント入口 |
| アカウントシート／承認待ち帯 | ドロワー下端またはホーム／ページ上部 | 既存導線と状態表示、セーフエリア、文字拡大 |
| 共通 UI 部品 | 対象画面内で利用 | Button、IconButton、Input、SegmentedControl、EmptyState、ErrorBanner、Loading、Drawer、Sheet の範囲内整合 |

既存のページスタック、ドロワーからの遷移、ページ内でのページ積み上げ、戻るボタン、Android 戻るキーを維持する。ホームの PC チャット表示中に接続が切れた際の一覧復帰、ログイン・規約ゲート、アカウント切替時のページリセットも変更しない。

## データ・API

- API、データモデル、保存形式、認証、セッション状態、料金計算は変更しない。
- 表示対象は既存データのみ。クラウド／PC セッション、接続可能 PC、状態、時刻、既知の料金、入力中の設定を既存条件に従って表示する。
- コスト不明時に金額を推定して表示しない。最近の会話取得失敗を空データとして扱わない。
- ループ用入力チップや新しい設定フィールドは追加しない。

## 受け入れ条件

### ホーム一覧

1. 既存テストデータでクラウド行、PC チャット行、PC デバイス行が同じ一覧に表示され、行選択、停止、PC 接続の各操作が従来どおり動く。
2. タイトル、状態、接続先／リポジトリ、時刻、料金の階層が視覚的に区別され、稼働中・承認待ち・失敗の状態は色を除いても状態名またはアイコンで判別できる。
3. 全て／稼働中／承認待ち／エラーの選択状態と件数が読み上げられ、該当データがない時は対応する空メッセージが表示される。既存のフィルター表示条件も維持される。
4. 初回ロード時はローディング、正常な空結果は歓迎表示、取得失敗は再試行付きエラーとなり、失敗時に正常な空状態を同時表示しない。更新中は保持済み一覧を消さない。
5. 起動中、起動失敗、PC 送信失敗、再試行不可／再接続案内が区別され、失敗後も既存仕様どおり本文が保持される。

### 入力欄

1. クラウド送り先では現行条件の設定チップとコストチップ、PC 送り先では送り先とコストが表示され、現行順序・表示条件が保たれる。ループチップは表示されない。
2. Web viewport 320 px、375 px とネイティブ狭幅で、送信ボタンは常時視認・操作可能であり、チップだけが独立してスクロールする。端のチップまでスクロールして到達でき、スクロール可能であることを識別できる。
3. 空入力時と PC 送信処理中は送信が無効であり、無効・処理中が視覚と読み上げの両方で分かる。送信可能時は既存の処理を一度だけ起動する。
4. 未設定・警告・設定確認中のチップ状態が読み取れ、状態を色だけで伝えない。入力、送り先切替、設定シート、コストシート、クラウド起動、PC 送信、再試行の既存動作に回帰がない。
5. キーボード表示中も入力欄と送信ボタンが遮蔽されず、入力欄の複数行入力とスクロールが機能する。

### ドロワー／アカウント／承認待ち

1. ドロワーを閉じた状態ではホームの本文幅が全幅で、見えないナビゲーション用余白・操作領域が残らない。開閉、背景タップ、閉じるボタン、Android 戻るキーで閉じられる。
2. PC 未接続でロックされたページは鍵と説明が表示され、押下時は既存案内が出る。接続可能なページは従来どおり開く。
3. 最近の会話は読み込み中／空／失敗を区別し、失敗時に再試行できる。会話選択とアカウント内の各導線が従来どおり動く。
4. 承認待ちがあるときのみ上部帯を表示し、「チャットへ」で PC チャットへ移動する。待ちがない時に帯の空白が残らない。
5. ドロワー、シート、承認帯の文字・ボタンがセーフエリアと重ならず、標準および拡大文字で切れない。

### 共通品質・幅・アクセシビリティ

1. Web 320／375／768 CSS px で横方向のページスクロール、要素の重なり、主要操作の欠落がない。768 px 以上でもタブバーや常設サイドバーが追加されない。
2. iOS／Android でノッチ等のセーフエリアとキーボード表示を確認し、OS の標準文字サイズと大きな文字（標準比 200% を目標）で主要文言・状態・操作が切れない。
3. スクリーンリーダーで各操作の名称・役割・選択／無効／展開／処理中状態が意味のある順序で取得できる。キーボード操作ではフォーカスが見え、入力欄から送信まで操作できる。
4. Web の文字色・背景色の実組み合わせを測定し、通常文字 4.5:1、大きな文字 3:1 を満たす。ネイティブの測定値はプラットフォーム別に記録する。
5. iOS は操作可能領域 44 pt を標準目標、Android は 48 dp を目標として測定する。例外や既存制約がある場合は対象・実寸・補完方法をレビュー記録に明記し、隣接操作との誤タップがない。
6. 型チェック、Jest、Web ビルドを実施し、対象画面の既存テストを含む結果を記録する。実機・スクリーンリーダー等の未実施項目は未検証として残す。
