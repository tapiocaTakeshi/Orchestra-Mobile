# UI改善の外部根拠を収集

UI改善の調査メモ（2026-11-09）

- **文字の読みやすさ:** React Native の `Text` は `allowFontScaling` が既定で有効で、OSの文字サイズ設定に応じた拡大をサポートします。固定高で文字を切らないようにし、大きな文字設定でもレイアウトを確認するのが適用条件です。AppleはDynamic Type等で文字を理想的には200%まで拡大可能にすることを推奨しています。出典: React Native「Text」（2026-10-28更新）https://reactnative.dev/docs/text ／ Apple「Accessibility」（2026-10-24更新）https://developer.apple.com/design/human-interface-guidelines/accessibility
- **配色とコントラスト:** WCAG 2.2 AAは通常の文字に4.5:1、大きな文字に3:1を求めます。Web表示には適合基準として適用し、ネイティブ画面では共通の設計目安として使う場合、プラットフォームの基準と区別して確認してください。色だけで状態を伝えず、文字・アイコン等も併用します。出典: W3C「WCAG 2.2」（2026-10-26更新）https://www.w3.org/TR/WCAG22/ ／ W3C「WCAG2Mobile」（2025-05-06公開、2026-10-02更新）https://www.w3.org/TR/wcag2mobile-22/
- **タップ領域:** AppleのiOS/iPadOSでは44×44 ptを標準サイズ、28×28 ptを最小サイズとして案内しています。MaterialではAndroid等のタッチ対象に48×48 dp以上、対象間に通常8 dp以上の間隔を推奨します。アイコンの見た目の寸法ではなく、操作可能な領域を測り、プラットフォームごとに単位・基準を使い分けます。出典: Apple「Accessibility」（2026-11-06更新）https://developer.apple.com/design/human-interface-guidelines/accessibility.md ／ Google Material「Accessibility」（2026-10-26更新）https://m1.material.io/usability/accessibility.html
- **情報階層:** 重要度に応じて項目を配置し、関連する項目を近くにまとめるのがMaterialの指針です。見出し・余白・文字の強弱で優先順位を伝え、既存機能や操作導線を変えずに整理する場合に適用します。出典: Google Material「Accessibility」https://m1.material.io/usability/accessibility.html
- **状態表示:** Material 3は有効・無効・フォーカス・押下などの状態を一貫して表し、アクセシビリティのため状態を示す視覚的手掛かりを2つ用いるよう案内しています。色に加えてラベルやアイコン等を使い、状態変化を判別できる設計が適用条件です。出典: Google Material 3「States」（2026-11-07更新）https://m3.material.io/foundations/interaction/states/overview
- **Expo/RNの適用:** Expo Imageの公式APIは、スクリーンリーダー向けの`accessibilityLabel`や要素のグループ化に関する`accessible`を記載しています。利用するAPI・プラットフォームにより挙動が異なるため、対象環境で確認してください。出典: Expo「Image」（2026-11-09更新）https://docs.expo.dev/versions/latest/sdk/image/

**前提:** 実際の採用技術・Expo/RNのバージョンおよび対象プラットフォームは未確認です。W3CのCSSピクセル、Appleのpt、Materialのdpは同一視せず、各プラットフォームで検証する必要があります。

この環境ではワークスペースの読み取り・書き込みツールが利用できなかったため、`.division/paper.md` は変更していません。

## 概要

- 最上位の目的は「デザインを改善して」。既存の暖色系ブランドと、ホームの一覧・入力・送信、設定、承認、ナビゲーションの操作を保ちながら、視認性と一貫性を高める（`.division/goal.md:6-8`）。
- 最優先は読みやすさと操作状態の識別、次にホームの情報階層・入力欄の整理、その後に共通部品とトークンの整合を図る。具体的な値や画面仕様は後続の Writer・Designer が決める。
- 以下ではソースを直接読んだ事実と、そこから導いた提案・未検証の仮説を区別する。実画面での欠陥や改善効果は未検証。

## 背景・目的

既存の `src/theme.ts:1-5,12-41` は暖かいオフホワイト、濃い茶の文字、主操作の控えめなテラコッタという方向性を明示している。`docs/design-claude-style.md:12,23-27` は見出し用セリフ体、抑制した影、既存の余白段階を説明している。全面的なブランド変更より、これらの特徴を活かした読みやすさと階層の調整を優先する。

対象は既存画面の情報階層、文字組み、余白、配色、共通部品、操作状態である。新機能、画面遷移や設定の意味・既定値の変更、不要な依存導入は対象外。見た目の変更によって操作を隠す場合も、既存の到達性を維持することを前提とする。

### 外部根拠と適用上の注意

冒頭の Searcher メモを引き継ぐ。React Native の文字拡大、WCAG の文字コントラスト、Apple／Material のタッチ領域、Material の情報階層と状態表示を、後述の優先順位の参考にする。通常文字4.5:1・大きな文字3:1は WCAG 2.2 AA の文字コントラスト基準であり、無効な操作要素などの例外がある。ネイティブでは同基準を設計・検証の参考とし、Web の適合性と混同しない。iOS の pt、Android の dp、Web の CSS px は同一視しない。冒頭にある出典の更新日や Apple の最小サイズ、Material の間隔などの細部は原典を本タスクで再取得できておらず**未検証**。最新の公式ページと実プラットフォームで後続確認する。

## アイデア・提案

1. **推奨案：既存レイアウトを保つ調整。** チップの順序・可読性・スクロールの発見しやすさ、一覧の題名とメタ情報の強弱、設定と警告の見分けを改善する。利点は主要動線とブランドを保ちやすいこと。リスクは横スクロール自体が残ること。送り先、場所、モデル、承認、並列数、コストの条件表示と到達性を維持し、変更前後で操作回数を比較する。
2. **代替案：設定情報をまとめる。** 既存シートへの入口をより明確にし、表示の密度を減らす案。利点は狭幅での整理、リスクは現在見える設定・警告・コストが隠れたり、確認操作が増えたりすること。主要情報の常時視認と既存操作回数を満たせない場合は採用しない。新しい設定・機能は追加しない。
3. **代替案：共通部品から先行調整。** ボタン、入力、状態ラベルの見た目とアクセシビリティを既存 UI から揃える。利点は横断的な一貫性。リスクは利用画面全体に回帰が波及すること。利用箇所と画面差分を洗い出し、ホームの局所改善に必要な範囲から適用する。

### 後続工程での確認方法

- Writer は対象画面ごとに、既存導線、操作状態、表示条件、フォーカスと読み上げ、文字拡大時の挙動を具体化する。特にクラウドのループチップは現行動作維持を前提に、不一致を残したまま機能追加しない。
- Designer は既存の色・書体・トークンを出発点に、標準幅と狭幅、大きな文字、キーボード表示、長文、空・読み込み・失敗・承認待ちを含む画面と操作状態を示す。見た目上の状態差と実際の読み上げ状態は別々に確認する。
- Coder／Reviewer は既存の `npm run typecheck`、`npx jest --runInBand`、`npm run build:web`（`package.json:8-12,20`）に加え、iOS・Android・Web の対象環境で実表示、スクリーンリーダー、キーボード操作、タップ領域、コントラスト、既存機能を確認する。文字拡大は OS 設定に加え、Apple の推奨する200%を目標に切れ・操作不能がないか確認する。端末・文字倍率・画面幅・測定した色の組み合わせと結果を記録し、未実施は未検証とする。
