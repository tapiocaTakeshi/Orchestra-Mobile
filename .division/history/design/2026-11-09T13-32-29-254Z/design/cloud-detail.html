  1. 接続状態: タイトル下に「未接続／接続中…／接続済み／接続切れ」を文字表示。

  4. 入力と回復: エラー、入力、送信を1つの視線内に置く。

操作仕様

  • 許可／拒否の処理中は両方を無効化し、押した側を「処理中…」にする。完了後はカードを「許可しました／拒否しました」に更新する。
  • 未接続時は会話とdraftを保持したまま送信・承認を無効化し、「接続後に操作できます」と理由を示す。
  • Android戻るは詳細情報シート→会話一覧の順。未送信文の破棄確認は自動保存されるため表示しない。
  • キーボードが開いてもerror・入力・送信を隠さない。320pxでは送信を全幅にして44px高さを維持。
  • 新着ログがあっても利用者が上を読んでいる最中は自動scrollせず、「新着メッセージ」ボタンを表示する。

実装メモ・受け入れ

pendingAction: { kind:'send'|'continueGoal', message:string } | null をsendErrorと対にする。retryは分岐せず通常sendを呼ぶのではなく、kindに応じて sendCloudMessage(auth,id,message) または sendCloudMessage(auth,id,message,{continueGoal:true}) を呼ぶ。sendingで再試行の重複だけを防ぐ。再試行buttonの実寸はminWidth/minHeight 44pt以上とし、汎用Buttonのsize='sm'は変更しない。pendingAction && sendable がfalseでも理由だけを残さず、再試行可否・不能理由・次操作の3状態を明示する。既存APIは変更しない。

自動テストで、空入力の継続失敗後も再試行が見えること、再試行時のkind・message・options一致、成功時のerror消去、draft編集・別操作成功時の古いerror消去、sendable=falseへの変化で再試行を消して理由と次操作を出すことを確認する。通常送信2操作と失敗後1操作は維持。2026-11-08: ISS-14の承認カード内disabledボタンを削除し、ISS-12の不能状態を追加。配色・承認カード自体・画面遷移は既存操作と互換性のため維持。
